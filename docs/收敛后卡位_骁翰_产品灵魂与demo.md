## 先说清楚一件事：投资人一定会问的那句

这场评委是投资人，不是工程师。跟随做得再稳，他们大概率会问同一句：

> **"会飞会走挺酷，可为什么非得两栖？装一台普通无人机，不也能跟拍吗？"**

这句答不上来，我们就是"贵一点的大疆"。答得死，两栖才从噱头变成护城河。**我来把这句答死——这是我这块的核心活儿。**

---

## 两栖非有不可的理由（产品的魂）

不吹技术，只讲投资人和用户听得懂的：

**理由一 · 一块电陪你一整天，不是拍 20 分钟就没电**
无人机跟拍最大的痛点就是续航——悬停是最耗电的姿态。会走的身体让它平时地面跟着你走（安静、省电、不扰），只在需要航拍的那一下才起飞。
→ 两栖 = 把"跟拍"从"拍一小段"变成"全天陪伴"。这是真实的电耗差异，不是编的（具体续航对比等实测数）。

**理由二 · 贴地的视角，普通无人机永远给不了**
地面时它能贴着地跟——宠物的狗视角、露营时的第一人称贴地镜头，这类素材在抖音/小红书是天然爆款；要全景了再起飞。
→ 两栖 = 视角自由，直接对上 C 端"想发好看内容"的付费意愿。

这两条都不依赖多聪明的板上 AI，靠的是**这具会飞会走的身体本身**——正好踩中赛题「智能为什么需要身体」。

## 让评委"哦"一下的那 30 秒（我做的 demo beat）

现场拿起手机，对它说一句话——

> **"跟穿红衣服的那个人"** （或"跟那只狗"）

机器就锁定那个目标开始跟。

**为什么这一下能回答赛题**：智能在这里不是给画面加滤镜，是把「人的一句话」翻译成「这具身体该去跟谁、用什么形态」。这就是"身体听懂了人"——评委要看的就是这个"哦"。

## 这个 beat 怎么做 / 48h 到底能不能出来（给徐梓阳、Jack）

跑在**地面端**（一台笔记本或手机），**完全不占那块 1GB 板子**，不动你们的板上跟随闭环：

- **语音入口在地面端，不在板子上**：说话是对着手机（或笔记本），不是对着无人机——板子没麦克风、飞起来螺旋桨噪音会盖过人声，48h 也塞不进语音识别。手机把语音转成文字（浏览器自带的语音转文字，或录一段音传给地面电脑用 whisper 转），识别出来的字实时上大屏；识别错了能秒改、或直接从画面点那个人。真正的"智能"是"文字描述→锁对目标"那步，语音只是入口糖，翻不了车。
- **输入**（都是你们现成的，不用重造）：RTSP 视频流 + YOLO 的结构化输出（target_id/类别/坐标）+ 遥测。
- **处理**：把"红衣服的那个"这类描述，对上 YOLO 输出里的某个 target_id（颜色/类别筛选 + 已有的跨摄像头 ID 匹配库，Jack 那份正好用上）。
- **输出**：把"跟这个 target_id"和"飞 / 走"回传给板子。

**我跟徐梓阳只需要一起定一条通道**：地面把「选中的 target_id + 形态指令」怎么回传给板子（HTTP 加个语义端点，或走 MAVLink，你定，你最清楚板上）。除了这一条，我不碰你的东西。

48h 能不能出来：能。地面端这块我这边可以先跑起来，等你甩一段样例录像 + 一份 YOLO 输出的 JSON 样例，我不等实机就能先调通。
