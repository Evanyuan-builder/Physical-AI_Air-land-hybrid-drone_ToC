## 先说清楚一件事：投资人一定会问的那句

这场评委是投资人，不是工程师。跟随做得再稳，他们大概率会问同一句：

> **"会飞会走挺酷，可为什么非得两栖？装一台普通无人机，不也能跟拍吗？"**

这句答不上来，我们就是"贵一点的大疆"。答得死，两栖才从噱头变成护城河。**我来把这句答死——这是我这块的核心活儿。**

## 两栖非有不可的理由（产品的魂）

不吹技术，只讲投资人和用户听得懂的：

**理由一 · 一块电陪你一整天，不是拍 20 分钟就没电**
无人机跟拍最大的痛点就是续航——悬停是最耗电的姿态。会走的身体让它平时地面跟着你走（安静、省电、不扰），只在需要航拍的那一下才起飞。
→ 两栖 = 把"跟拍"从"拍一小段"变成"全天陪伴"。这是真实的电耗差异，不是编的（具体续航对比等实测数）。

**理由二 · 贴地的视角，普通无人机永远给不了**
地面时它能贴着地跟——宠物的狗视角、露营时的第一人称贴地镜头，这类素材在抖音/小红书是天然爆款；要全景了再起飞。
→ 两栖 = 视角自由，直接对上 C 端"想发好看内容"的付费意愿。

这两条都不依赖多聪明的板上 AI，靠的是**这具会飞会走的身体本身**——正好踩中赛题「智能为什么需要身体」。

## 让评委"哦"一下的那 30 秒（我做的 demo beat）

现场拿起手机，对它说一句话——

> **"跟穿红衣服的那个人"** （或"跟那只狗"）

机器就锁定那个目标开始跟。

**为什么这一下能回答赛题**：智能在这里不是给画面加滤镜，是把「人的一句话」翻译成「这具身体该去跟谁、用什么形态」。这就是"身体听懂了人"——评委要看的就是这个"哦"。

## 这个 beat 怎么做 / 48h 到底能不能出来（给徐梓阳、Jack）

跑在**地面端**（一台笔记本或手机），**完全不占那块 1GB 板子**，不动你们的板上跟随闭环：

- **大脑放地面端跑——不是板子做不到，是这块 1GB 板做不到**：MaixCAM2 本体其实很强，板载双麦克风+扬声器，官方还支持离线跑语音识别和视觉语言模型（VLM）。但那基本要 4GB 版，我们这块是 1GB、48h 内不能换板；1GB 已经喂满了 YOLO 跟随+图传，再叠一层语言/VLM 会把内存抢崩。所以这次把"听懂人、挑对人"这层放地面端（一台笔记本/手机）跑：不抢板子内存、不动梓阳的板上管道、demo 稳，我还能不等实机先跑通。
- **地面端具体怎么接**：手机/笔记本收音→转文字（浏览器自带语音转文字，或录音传地面电脑用 whisper）→地面 agent 拿 YOLO 输出把"红衣服的那个"对上某个 target_id（颜色/类别筛选，复杂描述可挂个小 VLM）→把"跟这个 id、飞/走"回传给板子。识别的字实时上大屏，错了能秒改或直接点画面里那个人——语音只是入口糖，真正的智能是"描述→锁对目标"那步，翻不了车。
- **接口清单**（都是你们现成的，不用重造）：地面端要读的=RTSP 视频流 + YOLO 结构化输出（target_id/类别/坐标）+ 遥测；地面端要回传的=选中的 target_id + 飞/走。跨摄像头 ID 匹配库 Jack 那份正好接上。

**我跟徐梓阳只需要一起定一条通道**：地面把「选中的 target_id + 形态指令」怎么回传给板子（HTTP 加个语义端点，或走 MAVLink，你定，你最清楚板上）。除了这一条，我不碰你的东西。

48h 能不能出来：能。地面端这块我这边可以先跑起来，等你甩一段样例录像 + 一份 YOLO 输出的 JSON 样例，我不等实机就能先调通。

## "为什么不直接在板子上做？"——投资人会问，我们的答案很干净

MaixCAM2 官方就支持板上离线跑语音识别 + 视觉语言模型（12.8 TOPS 的 NPU、板载双麦+扬声器）。所以这条产品线不是画饼：

- **今天的 demo**：大脑放地面端，是 1GB 版 + 48h 的务实选择——先把"听懂人、挑对人"稳稳演出来。
- **产品版**：同一套逻辑塞进 4GB 版板子，机器本体直接听你说话、还能开口应答。硬件官方已支持，工程量是"搬进去"不是"从头造"。

一句话对评委：**这具身体今天已经听懂人了，明天连地面电脑都不用——路我们看得很清楚。**
